There are two bugs with the AI Service Inquiry page that need fixing.

## Bug 1: Response handling always shows rejection message

File: artifacts/agent-hub/src/pages/ai-service-inquiry-page.tsx

The Make.com webhook is fire-and-forget — it queues the request and returns a generic acknowledgment (not the actual AI evaluation result). But the current code tries to read `can_help`, `reason`, and `matched_service` from the response, which don't exist. This causes the UI to ALWAYS show the amber "Thank you for your interest! Unfortunately..." rejection message, even for valid inquiries.

Fix the success state to always show a single positive confirmation, since we can't know the AI's decision in real time:

1. Remove the `canHelp` / `reason` / `matchedService` / `makeResponse` derived state variables entirely. They are not usable with a queued webhook.

2. Replace the conditional success rendering (the whole `canHelp ? green : amber` block) with a single success card:
   - Use the GREEN style: `border-green-500/30 bg-green-500/5`
   - Icon: `CheckCircle2` (green, NOT AlertTriangle)
   - Heading: "Inquiry Submitted Successfully!" (in green-300)
   - Body: "Thank you! Our AI is evaluating your project and matching the right solution. You'll receive an email shortly with your proposal, NDA, invoice, and DPA."
   - Keep the existing "Submit Another Inquiry" button below

3. The `InquiryResult` interface and the `setResult(data)` call can stay (we still need to know the request succeeded), but don't try to extract `can_help` or `reason` from it.

4. Keep the error handling as-is — if the webhook returns non-2xx or network fails, still show the error toast.

## Bug 2: Published deployment doesn't match dev

The published deployment is serving a stale build. After making the fix above:

1. Delete the existing build output: `rm -rf artifacts/agent-hub/dist`
2. Rebuild the frontend: `pnpm --filter @workspace/agent-hub run build`
3. Rebuild the API server: `pnpm --filter @workspace/api-server run build`
4. Go to the Deployments tab and click "Redeploy" to push the fresh build to the published URL

The dev preview uses Vite's dev server with hot reload (changes show instantly), but the published deployment serves pre-built static files from artifacts/agent-hub/dist/public. Every time you make code changes, you need to rebuild + redeploy for the published URL to update.
